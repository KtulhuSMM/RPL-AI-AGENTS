# RPL AI Agent — план реализации

## Главная стратегия

Не пытаться сразу создавать «идеального AI-агента». Проект развивается слоями:

**UI → реальные данные → prediction engine → AI → история качества → монетизация.**

Каждый этап должен завершаться работающей версией, которую можно показать другому человеку.

---

## Ограничение scope

Вся реализация roadmap относится **только к РПЛ**. Не проектировать функции, модели данных или интерфейсы под другие турниры, если это не нужно текущей версии РПЛ-продукта.

Перед спорным продуктовым решением сверяться с `docs/PRODUCT_QUESTIONS.md`.

# Этап 2 — тест и подключение реальных данных РПЛ

**Срок: 3–7 дней**

### Решение по источнику

Первым тестируем **API-Football Free**. Полный протокол проверки находится в `docs/API_FOOTBALL_TEST.md`.

Платный тариф на этом этапе **не покупать**. Сначала подтвердить фактическое покрытие РПЛ, качество данных и достаточность Free rate limit при кэшировании.

### Этап 2A — diagnostic test API-Football Free

**Срок: 1–2 дня**

- [ ] получить бесплатный API key;
- [ ] сохранить его только в `.env`;
- [ ] найти РПЛ через leagues endpoint;
- [ ] подтвердить league ID;
- [ ] получить coverage и доступные сезоны;
- [ ] получить команды сезона;
- [ ] проверить fixtures/results;
- [ ] проверить standings;
- [ ] проверить 3–5 матчей на match statistics;
- [ ] отдельно проверить lineups / players / injuries;
- [ ] зафиксировать null/пропуски;
- [ ] оценить расход запросов;
- [ ] заполнить журнал в `API_FOOTBALL_TEST.md`.

### Gate после 2A

Интеграцию продолжаем только если API стабильно отдаёт минимум команды, fixtures/results, standings и устойчивые ID. Расширенная статистика является преимуществом, но её отсутствие не блокирует базовую Poisson/Elo модель.

### Этап 2B — интеграция подтверждённых данных

**Срок: 2–5 дней**

- [ ] создать `src/api_football.py`;
- [ ] реализовать API client;
- [ ] не обращаться к API напрямую из Streamlit UI;
- [ ] нормализовать команды и матчи во внутренний формат;
- [ ] заменить mock-матчи подтверждёнными реальными данными;
- [ ] заменить mock-таблицу реальной;
- [ ] добавить кэширование;
- [ ] fallback на локальные/mock данные при ошибке API;
- [ ] корректно обработать rate limits и timeout;
- [ ] логировать время последнего успешного обновления.

### Definition of Done

Приложение показывает актуальные данные РПЛ через API-Football Free, а отсутствие API или расширенной статистики не ломает основной интерфейс.

# Правила работы Codex над проектом

Перед крупным изменением Codex должен:

1. Прочитать `docs/SPECIFICATION.md`.
2. Прочитать `docs/ROADMAP.md`.
3. Определить текущий этап.
4. Не внедрять функции следующих этапов без необходимости.
5. Сохранять простую архитектуру.
6. После изменений запускать приложение и исправлять ошибки.
7. Не менять публичный UX без причины.
8. Не помещать секреты/API keys в код.
9. Не позволять LLM самостоятельно генерировать числовые прогнозы.
10. При изменении архитектуры обновлять документацию.
